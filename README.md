## 导入小程序

在微信开发者工具中分别导入对应案例下的 `案例实现` 目录，不要把仓库根目录或 `服务器端` 导入为小程序。项目配置中的 `touristappid` 仅用于无账号的本地导入；微信登录、后台音频和位置服务的实际使用需要满足微信平台的账号及权限要求。

服务端地址按 PDF 使用本机 `127.0.0.1:3000`（头像上传为 `localhost:3000`）。本地联调时按 PDF 在微信开发者工具中勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。该设置只针对教材中的本地接口调试，不改变 npm 安装或外部 HTTPS 请求的证书校验。

真机中的 `127.0.0.1` 指手机自身；本仓库按 PDF 的电脑模拟器联调方式实现。

## 服务端安装与启动

使用 Node.js 与 npm。在需要服务端的案例的 `服务器端` 目录执行：

```sh
npm ci --ignore-scripts --no-audit --no-fund --registry=https://registry.npmjs.org --replace-registry-host=always
node index.js
```

资源包的旧锁文件包含镜像站下载地址，上述安装参数使用 npm 官方仓库，并保留锁定版本及完整性校验；`--ignore-scripts` 使用聊天库自带的 JavaScript 回退实现，无需编译旧的原生扩展。

音乐播放器、头像上传下载、用户登录和在线聊天各自提供独立服务端，均使用教材中的 3000 端口。每次启动一个案例的服务，切换案例前用 Ctrl+C 结束当前服务。录音机、模拟时钟、罗盘动画和餐厅案例不需要这些本地服务。

头像服务所需的 `htdocs/upfile` 目录已保留，上传产生的图片不提交到 Git。

### 用户登录的必要配置

按照 PDF，在 `【案例5-2】用户登录/服务器端/index.js` 的 `wx` 对象中填写自己的真实 `appid`、`secret`，并在微信开发者工具的项目设置中使用同一个 AppID。AppSecret 仅放在自己的服务端本地配置中，不提交包含真实密钥的文件。测试账号无法完成真实 `code` 换取会话。

登录成功后，点击“获取用户的积分”，按照 PDF 在开发者工具控制台查看返回结果，初始积分为 100。选择头像和填写昵称只更新页面，未添加用户资料保存功能。

### 附近餐厅的必要配置

在 `【案例5-3】查看附近的美食餐厅/案例实现/config.js` 填写自己申请的腾讯位置服务微信小程序 Key，并为相应小程序开通服务、配置 `https://apis.map.qq.com` 请求域名及微信位置接口权限。用户需授权定位。未填写 Key 时不会伪造餐厅数据；优惠券页仍可打开。

## 自动化检查

先为上述四个服务端安装依赖，然后在仓库根目录运行（Node.js 24）：

```sh
node --test tests/*.test.js
```

检查共 14 项，涵盖页面及素材引用、8 个案例的业务逻辑，以及真实 HTTP 音频/Range、头像上传下载、登录未授权接口、WebSocket 自动回复和控制台主动推送。测试顺序启动并关闭自身服务，3000 端口需空闲，测试上传文件会清理。

小程序端检查使用模拟的 `wx` API；登录完整流程中的微信响应也是模拟数据，用于验证 token、会话和积分逻辑，不能代替真实微信账号联调。微信界面渲染、录音硬件、后台音频、真实登录、位置授权和真实餐厅检索需在微信开发者工具或设备上验收。
